# SCARECROW V4 — Wheat emblem, holder participation, coin & trading age

## Exact deliverable and compatibility

- **Apply V4-from-live-V2.zip** to a Git checkout that is currently running **V2** (this includes the V3 shared-community board from the earlier update).
- **Apply V4-only-from-V3.zip** if your project already contains **all V3 community changes**.
- Both ZIPs have repository-relative paths. Extract into the `scarecrow-scanner-github` checkout and overwrite matching files. Never unzip into a nested folder inside the repo.
- These files were **not pushed to your GitHub repository or deployed by this assistant**.

## Data sources used

| Observation | Default feed | Requires payment/key? | Notes |
|---|---|---|---|
| Observed token holders | GeckoTerminal public token info | No; 30 API calls/min rate limit | Can return null; five-minute per Worker-isolate cache |
| Holder count, mint creation time, first indexed listing | Solscan Pro token/meta and token/statistic | Optional Solscan Pro API key (`SOLSCAN_API_KEY`) | Separate endpoints; statistic may require higher plan; ten-minute per-isolate cache |
| Earliest currently indexed DEX pair created | DEX Screener | No | Not proof of original first trade or token launch |
| Market cap / holder | DEX Screener market cap + indexed holder count | No if Gecko works | Does not use FDV as market cap, does not reveal holder balances |
| Streamflow lock verification | **Not yet live** | Requires a protocol-verifying backend | UI shows NOT VERIFIED and links to Streamflow; no positive grade credit without verified on-chain contracts |

The scanner intentionally does **not** infer that labeled Streamflow token accounts are non-cancelable locked contracts. Claims about circulating supply cannot be inferred solely from token-account owner labels. Contract data must be checked (mint, amount still inaccessible, lock/release schedule, cancelability, restrictions); exchange-quoted market capitalization should not be adjusted ad hoc for assumed locks. The grade engine contains a *disabled-by-default* validated-evidence input for eventual first-party Streamflow SDK integration, but **V4 does not fetch verified contracts**, so lock bonuses are not currently awarded.

## Grade policy (not a safety verdict)

- Holder-count contribution: +1 for 50+, +3 for 150+, +6 for 500+ observed holders, if an indexed pair exists.
- Participation-density contribution: +1 / +2 / +3 for 50 / 100 / 200 holders per $100k observed market cap, only if 100+ holders, $10k+ cap, and $10k+ liquidity; no credit from FDV-only prices.
- If Solscan provides top-20 ownership concentration and this is >=75%, score -5. LP vaults / custody may affect this measure.
- Observed indexed trading age: +1 at 7 days, +3 at 30 days, +4 at 90 days. No penalty for a newer pool without independent evidence.
- Confirmed lock signal (+4) remains inoperative until protocol verification is wired. Missing observations are displayed as unavailable, not zero or safe.
- Existing verified on-chain authority warnings and data-confidence caps remain active. A DEX-only grade is capped at **77 (C+)**, regardless of holder count.
- The ratio is `market cap / observed holder addresses`, *not* mean holdings, supply held by community, genuine wallets, or holding duration. It is vulnerable to dusting, duplicate wallets, Sybil attacks, custodial addresses, and stale indexer data.

## Deploy safely

1. Apply your appropriate ZIP to `C:\Users\oreo3\OneDrive\Desktop\scarecrow-scanner-github`.
2. Run:

```powershell
cd "$HOME\OneDrive\Desktop\scarecrow-scanner-github"
npm install
npm run test:scanner
npm run test:community
node --test tests/intelligence.test.mjs
npm run build
```

3. Check generated `.output/server/wrangler.json`: its Worker name **must be `scarecrow-scanner`** and not an autogenerated folder-based name. `nitro.config.ts` pins it to the current production Worker.
4. **The integrated V3 community features require Cloudflare D1.** If this is your first V3/V4 deployment, follow `docs/V3_COMMUNITY_SETUP.md` *before* pushing if you expect public votes and suggestions to work. This uses a separate D1 database, `SCARECROW_D1_DATABASE_ID` build variable and `SCARECROW_SESSION_SECRET` Worker runtime secret. Scanning works without D1, but public posting will be offline.
5. You can optionally add **SOLSCAN_API_KEY** as a Worker runtime secret (do not use `VITE_*`, do not put it in the ZIP). Without it, the app will use GeckoTerminal when it returns holder counts; token creation age may remain unavailable. Solscan Pro API plans can have ongoing fees; not necessary for the free Gecko path.
6. Verify no errors then push to main:

```powershell
git status
git add -A
git commit -m "SCARECROW V4 holder metrics, token age and wheat branding"
git push origin main
```

7. In Cloudflare → Workers & Pages → `scarecrow-scanner` → Deployments, check the new commit is deployed and active. Refresh browser tab in an incognito window to bypass favicon cache; `?v=4` asset version is included.
8. Test CROW by entering `GtV6g1ey2NERrcbvL5bdzrxRJQDfxpMaLU9oLtRipump`. Holder count availability depends on the data provider at test time; lack of a response must display UNAVAILABLE rather than a fabricated number.

## Local validation and production limitations

- All 29 logic tests passed (`scanner`, `community`, `intelligence`).
- Updated TSX files passed TypeScript *syntax parsing* without compile diagnostics.
- A full production Vite build was NOT possible here because npm dependencies are not locally installed and the sandbox cannot reach the npm registry. Run `npm install` and `npm run build` on your Windows checkout before pushing.
- Remote Solscan / GeckoTerminal response and Streamflow protocol integration were not exercised live in this sandbox. No current CROW holder count or locked amount has been independently asserted.
